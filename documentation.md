# AnkSetu — Documentation

AnkSetu (अंकसेतु) is a web app that explains India's official statistics from **MoSPI** (Ministry of Statistics and Programme Implementation) in plain English and Hindi. It covers retail inflation, GDP, industrial output and jobs. Every number shows its source release, and the app says so when it has no official figure instead of guessing.

> AnkSetu is an independent app built on MoSPI's open data. It is **not** an official Government of India website, and it must not use the State Emblem.

---

## Quick start

```bash
cd ~/Desktop/mospi
node dev.js            # local preview → http://localhost:3000
vercel --prod          # deploy to production (Vercel)
```

Requirements: Node 18+ and the Vercel CLI (`npm i -g vercel`). The project has no dependencies and needs no `npm install`.

Don't open `index.html` by double-clicking it. Served from a plain file, the app can't reach `/data.json`, so it falls back to the built-in snapshot. Always preview with `node dev.js`.

## How live data works

```
api.mospi.gov.in  →  api/data.js  →  /data.json (no cache, fresh each load)  →  index.html (polls every 5 min)
```

1. **First load.** The app shows a loading skeleton and requests `data.json`, waiting up to 8 seconds (10 at most as a hard stop).
2. **`api/data.js`** calls the MoSPI API for the latest **CPI, IIP, GDP, PLFS (monthly) and PLFS (quarterly states)** data, plus recomputed "states like X" groupings. It always sends the latest data, and the app ignores anything older than its snapshot.
3. **The app** validates every block (`applyLive` → `BUILDERS`) and applies the valid ones on top of the snapshot. Invalid blocks are rejected and listed on the Sources screen.
4. If `data.json` is unreachable, the app shows the **built-in verified snapshot** and says so.
5. After that the app re-checks every 5 minutes. Nothing is cached server-side, so each page load or refresh fetches fresh data from MoSPI, and whenever the tab becomes visible again.

### What is live vs. snapshot

Every dataset the app shows is fetched live. Only the release calendar, the Outlook projections and release PDF links are hardcoded. See [data-inventory.md](data-inventory.md) for the full list, endpoints and notes.

MoSPI usually releases CPI around the **12th**, monthly PLFS around the **15th** and IIP around the **28th** of the following month. Quarterly GDP comes about two months after the quarter ends. New data appears on the next page load after MoSPI publishes it.

### Status indicator

The sidebar's status box shows a **green dot** ("Live from the MoSPI API") when a live block was applied, and an **orange dot** ("Built-in verified snapshot") otherwise. On the Sources screen, each dataset shows whether it was fetched from the API or read from the release.

### TLS note

`api.mospi.gov.in` requires legacy TLS renegotiation, which Node's `fetch` refuses. `data.js` therefore uses `https` with an agent that enables `SSL_OP_LEGACY_SERVER_CONNECT`. Certificate verification stays **on**.

## The app (`index.html`)

A single self-contained file with no framework and no build step. The whole UI is re-rendered as an HTML string by `render()` into `#app`. Clicks are handled by one delegated listener based on `data-act` attributes.

### Screens (tabs)

| Tab | Function | What it does |
|---|---|---|
| Home | `screenHome` | Headline tiles (inflation, GDP, IIP, unemployment) with green/red change badges, plus your state |
| Ask | `screenAsk` | Free-text questions in English or Hindi, answered only from official figures |
| States | `screenStates` | Tile map, ranking and comparison for all states/UTs; "states like X" (k-means) |
| Industry | `screenIndustry` | GVA by industry, IIP sectors, use-based categories, NIC groups |
| Outlook | `screenOutlook` | ARIMA projections FY2026-27 to FY2030-31 with 80% bands (labelled *not official*) |
| Prices | `screenPrices` | Personal inflation calculator; entries stay in the browser |
| Check | `screenCheck` | Fact-checks a pasted claim against official figures (no model involved) |
| Sources | `screenSources` | Release links, dates, upcoming calendar, models, safeguards, glossary |

### Key globals

| Name | Purpose |
|---|---|
| `PD` | Period of each series (e.g. `PD.c = {y:2026,m:9}` for CPI). All month/quarter labels are derived from it |
| `SNAP` | Date the embedded snapshot was read (`'2026-10-18'`) |
| `SRC` | Source release per dataset: name, release date, status, PDF URL |
| `DATA` | National figures: `DATA.cpi`, `DATA.gdp`, `DATA.iip`, `DATA.plfs` |
| `CPI_ST`, `LFPR_ST`, `WPR_ST`, … | State-level tables |
| `UPCOMING` | MoSPI release calendar, used to warn when newer data may be out |
| `ML_INTENT`, `ML_PEERS` | Embedded text classifier and k-means state groupings |
| `OUTLOOK` | ARIMA projection results |
| `BUILDERS` | Validators and appliers for live blocks: `cpi`, `iip`, `gdp`, `plfs`, `plfsq` |
| `LIVE` | Live-data status: applied blocks, rejections, last error |
| `state` | UI state: tab, language, theme, text size, inputs |

### UI shell

- `header()` / `headTools()`: navy header with logo, clock, text size (A− A A+), light/dark toggle and EN/हिं.
- `sidebar()`: desktop (≥960px) navigation and live-status box. Mobile uses the bottom tab bar `nav()`.
- `footer()`: official source links and the independence disclaimer.
- `shell(inner)`: assembles all of the above. `skeleton()` is shown while the first live fetch is in progress.
- Icons are inline [Lucide](https://lucide.dev) SVGs (ISC licence) in `ICON`.
- Fonts are Noto Sans, Noto Sans Devanagari and Noto Sans Mono (figures), loaded from Google Fonts.

### Saved preferences (`localStorage`)

| Key | Values |
|---|---|
| `anksetu-lang` | `en` / `hi` |
| `anksetu-theme` | `light` (default) / `dark` |
| `anksetu-fs` | `s` / `m` / `l` (text size) |
| `anksetu-fb` | Local log of 👍/👎 feedback on answers (downloadable as CSV from Sources) |

### Change badges

Home tiles colour their ▲/▼ badge by meaning, not direction. Rising GDP or IIP is **green**; rising inflation or unemployment is **red**. The rule lives in `tile()` (`badUp` = `cpi`, `plfs`).

## Common tasks

### Refresh the built-in snapshot (optional)

The snapshot is only a fallback for when the API is down. To refresh it, update `DATA`, the state tables, `INDUSTRY`, `SRC`, `PD` and `SNAP` in `index.html`. You don't need to change anything in `api/data.js`.

### Add another live dataset

1. Find the endpoint and parameters in NSO's Swagger specs (github.com/nso-india/esankhyiki-mcp, `swagger/` folder) or in `API government.docx`.
2. Add a `xxxBlock()` in `api/data.js`. Return the shape the app's `buildXxx` validator expects, and add it to `build()`.
3. If the app has no validator for it yet, add one to `BUILDERS` in `index.html`.

API quirks:
- `limit` is 10–200.
- NAS takes one indicator per call.
- PLFS takes one indicator per call.
- Monthly PLFS is All India only.

### Test the API function on its own

```bash
node dev.js
curl http://localhost:3000/data.json
```

`errors` lists blocks that failed. `skipped` lists optional parts that were dropped while the rest of the block was still sent.

## Principles (keep these when changing things)

- **Official numbers only.** Every figure carries its release, date and status. If there is no official number, say so.
- **Models are labelled.** Classifier, k-means and ARIMA outputs are marked *Model* and never presented as official statistics. The Check screen never uses a model.
- **Right place, right time.** Questions about other countries, periods, cities, districts or forecasts are not answered with a nearby figure.
- **Privacy.** Personal spending entries and feedback stay in the browser.
- **Bilingual.** Every user-facing string goes through `L('english', 'हिंदी')`.
